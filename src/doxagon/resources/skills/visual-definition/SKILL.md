# Visual definition

## Prerequisites

1. Run `dox doctor` and fix every failing check.
2. Run `dox context <project>` to identify the rendering model.
3. Run `dox document context --project <project> --json` before changing a document-model visual.

Definitions declare styles, configuration, sources, and visual description. Assemble and inspect an exact generation plan with `dox document generation-plan`; this is the review artifact before any paid provider call. Reference closure order is fixed and provider capability limits are never bypassed.

Keep semantic visual constraints in definitions: use the project style system rather than color names, hex values, or font specifications. Do not drop references or alter an assembled prompt after review.
