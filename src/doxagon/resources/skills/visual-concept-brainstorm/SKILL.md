# Visual concept brainstorm

## Prerequisites

1. Run `dox doctor` and fix every failing check.
2. Run `dox context <project>` to load the argument sources and authoritative model.
3. Read the project style documentation named by the context before proposing visuals.

Develop concepts from the slide or cue's claim, its narrative position, and the visual system. Name focal point, visual metaphor, key elements, and the communication purpose for each concept. Recommend one concept and draft a semantic definition only after the argument and design constraints are understood.

Consider motion when the claim is a sequence, a change of state, or an interaction. An animated concept names its cue holds and decomposes into image components that can each be generated: object layers, actors, looping parts, emblems. [Presentation motion](./../presentation-motion/SKILL.md) has recipes and samples. A static plate remains the default when time adds nothing.

Do not assume an active presentation, invent a provider-specific prompt dialect, or substitute decoration for the claim the visual must communicate.
